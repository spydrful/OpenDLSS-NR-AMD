# OpenNR AMD Alpha 5

An **experimental Windows build for Radeon RX 9070 XT and Cyberpunk 2077**. This release is for trying and validating neural rendering (NR); performance and broad game-quality targets remain unmet. **NR starts disabled.**

## What changed

- Adds optional Pair/Arena processing paths that reduce network-only GPU time in the recorded comparison.
- Fixes a correctness problem found by broader checks of some earlier experimental kernels; the published alpha 4 Direct-RTE path is unaffected.
- Keeps these new paths optional; installing this build does not select them automatically.

This is an older development release. [Alpha 6](https://github.com/spydrful/OpenDLSS-NR-AMD/releases/tag/v0.1.0-alpha.6) contains the newer work; use this page when testing or returning to alpha 5.

## Get started

The tested setup is **Windows 11, RX 9070 XT, Adrenalin 26.9.1 and Cyberpunk 2077 2.31**, plus **PowerShell 7**, the **Microsoft Visual C++ v14 x64 runtime**, and your own supported local model DLL (pinned DLSS-NR 310.8.0 or 310.8.SF.0).

1. Download the ZIP and checksum, verify the hash, and extract the package. Keep it for removal.
2. Close the game. Follow the [installation guide](https://github.com/spydrful/OpenDLSS-NR-AMD/blob/v0.1.0-alpha.5/docs/INSTALL.md) to install into the folder containing `Cyberpunk2077.exe` (normally `bin\x64`). Preview the install with `-WhatIf` first.
3. Import your supported model locally using the guide. The importer reads the DLL without executing it; reuse an existing verified model rather than overwriting it.
4. Start with **2560 × 1440 output, FSR Quality, ray tracing off, frame generation off and driver AFMF off**. Launch the game, then press **Insert → Neural → Enable NR** when ready to test.

Use **Enable NR** to turn inference off again. Setting effect strengths to zero still runs the network.

## Upgrade or go back

Close the game and remove the current OpenNR installation using its own retained package before installing another version. Keep the extracted packages, the game's `.open-nr-install.json` ledger and `.open-nr-backup-*` folder. The scripts verify managed files and restore backed-up originals.

If you edited a managed INI or another installed file, preserve it and follow the guide before uninstalling; changed managed files can block removal. Imported models remain after uninstall. To return to an earlier release, uninstall this one, install that release using its own package and guide, and keep its packaged defaults.

## Known limits

The recorded 13.9458% improvement measures network-only GPU time against the frozen alpha 4 route. Alpha 5 game FPS, bridge time and VRAM were not measured.

Broad motion, faces, disocclusion, exposure, ghosting and highlight acceptance remain incomplete. Some HDR/highlight reference-quality checks still fail. Original NVIDIA-runtime parity, RX 7000 acceleration, other games/platforms, ray tracing and HDR display validation are unclaimed. The full validation scope and measurements remain below.

[Report an issue](https://github.com/spydrful/OpenDLSS-NR-AMD/issues/new) with the release version, GPU/driver, game settings, selected NR options and exact error text. Keep proprietary DLLs, model files and game captures out of attachments.

the native AMD Vulkan runtime and D3D12 bridge. NR ships **disabled**. The
existing qualified auto cache and K16 defaults stay unchanged; Pair/Arena

## Measured network improvement

The repaired Pair/Arena Q32 candidate improves ordinary target network median
**58.684860 → 50.500780 ms**, P95 **58.922124 → 50.689466 ms** and P99
**59.053322 → 50.815118 ms**: **13.9458% median improvement** against the frozen
published alpha 4 Direct-RTE/Register-RTE route. Both use K16, N16/stage16/Q32,
valid **1707×960** input and **1728×960** padded model geometry, with every
fusion/packed-publication experiment off.

Three interleaved pairs each use five warmups and 30 measured frames, retaining
90 samples per condition without readback or dispatch instrumentation. Windows
11, RX 9070 XT, Adrenalin 26.9.1 (LLPC) and Vulkan 1.4.349 are the tested
environment. These are **network-only GPU timestamps**, excluding the bridge,
FSR, game and presentation. Alpha 5 game FPS, game bridge timings and VRAM are
unmeasured. The **8 ms NR-plus-bridge** and **16.67 ms / 60 FPS** targets remain
unmet.

Separate instrumented family medians are **38.933 → 32.151 ms GEMM** and
**7.983 → 6.480 ms attention**. The 1080p geometry comparison retains the same
90-sample protocol and measures **78.576 → 68.384 ms** ordinary network median
at 1920×1080, padded to 1920×1152. It establishes no additional 1080p image or

## Included changes and erratum

- `direct-rte-pair` preloads two original K16 operand fragments for K >128 while
  retaining ordered matrix publications and partition updates. It currently
  requires N16/stage16 and the SiLU epilogue's half/F32 float controls.
- `arena-rte` reuses shared score, weight and output scratch storage with explicit
  barriers. Declared LDS is 6,656 bytes at Q16 and 9,216 at Q32. Key order,
  reductions, learned priors, shifted windows, padding and publication remain
  strict; the allocation reduction alone is not an occupancy claim.
- Expanded tests expose a valid K192/P96/two-batch failure of 10,477 bytes in
  historical Init/Epilogue and initial Pair modules. Current modules retain the
  original initializer for every partitioned operator; the runtime-zero shortcut
  is limited to non-residual, unpartitioned K ≤512. Historical 880-check reports
  keep their hashes but cannot qualify this wider contract. Alpha 4's published
  Direct-RTE module and qualified cache are unaffected.
- Explicit CLI/environment selectors, module identities, geometry guards and
  proof checks recognize the new routes. No Pair/Arena auto cache is promoted.
  K32/final accumulation fails the incremental HDR quality screen and stays
  experimental. The portable reference and v1 C ABI remain unchanged.

## Completed validation and remaining limits

Init/Arena Q32, Epilogue/Arena Q32 and Pair/Arena Q16/Q32 each pass **724
operators / 934 strict byte checks / 15,264,768 bytes**. Pair/Arena Q32 formal
model proofs pass all 75 boundaries plus the F32 head and capture reproduction
at 320×320; the target proof covers head and capture reproduction. All 75
target boundaries are not claimed. Six synthetic SDR/HDR cases match the prior
AMD K16 route, retaining existing absolute-reference highlight limitations.

Eight existing genuine SDR game frames pass **80 raw byte checks /
2,107,883,520 bytes** and 16 exact composed RGB comparisons in identical and
independently evolved histories. Evolved history uses each variant's own outputs
from reset and does not claim original captured ancestry. No new game capture
or visual scene coverage is added.

Actual runtime-DLL ABI/lifecycle checks pass with eight sequential requested
frames at 320×320 and target geometry. A separate source-included production-pool
harness verifies eight live prepared slots at full target resolution before
submission: serialized/prefetched equality across eight ordered frames and seven
cancel/gap/reset outputs. Controlled shared-resource/fence, state continuation,
failure recovery, resize and drain/shutdown checks pass. These readback tests
do not measure concurrent inference or game performance. Driver resource/ISA
inspection records static matrix delivery; an RGP capture and spill counts are
not claimed. The Vulkan validation layer was absent.

Broad motion/face/disocclusion/exposure/flicker/ghosting review, full highlight
quality acceptance, new complete Cyberpunk benchmarks and ten minutes of active
gameplay remain outstanding. Original NVIDIA parity, RX 7000 acceleration,
other games/platforms, ray tracing and HDR display validation are unclaimed.

model DLL locally; the importer reads it without executing it. Downloads retain
MIT core/importer attribution, GPL host corresponding source and all dependency
notices, with reversible hash-checked install/remove scripts. Package and
corresponding-source checks are recorded separately at final delivery.
