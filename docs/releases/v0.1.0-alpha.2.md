# RX 9070 XT native Windows alpha 2

This alpha adds compact AMD attention kernels, diagnostic kernel selectors,
identity-bound K16 tuning, per-dispatch GPU profiling and bounded sequence
capture to the native Vulkan runtime and D3D12 OptiScaler integration for
**Cyberpunk 2077 on RX 9070 XT**. It remains a development release:
**performance and game-quality gates are unmet, and NR ships disabled**.

The latest ordinary idle-GPU network comparison measures **141.343 → 122.331 ms
median**, **143.036 → 123.263 ms P95** and **143.603 → 123.534 ms P99** at
1707 x 960 valid input, padded to 1728 x 960. Three interleaved legal Q64/Q32
pairs each use five warmups and 30 measured frames. The median falls **13.45%**,
with K16 arithmetic and fusion and
hardware-publication overrides off. These are network-only GPU timings;
**they are not game FPS or NR-plus-bridge timings**. Three NR-off Cyberpunk
benchmarks report 99.58 / 99.32 / 101.74 FPS; the first ordinary NR-on pass
reports **7.51 FPS** (972 frames, 129.51 seconds). Frame generation and driver
AFMF were observed off. Two further NR-on passes, ten-minute active gameplay
and broad temporal review remain pending. The 8 ms NR-plus-bridge and 60
rendered FPS targets remain unmet.

The earlier **206.167 → 120.271 ms / 41.7%** network result remains historical:
it used the original legacy attention, whose shared-memory requirement exceeds
this device's limit. The new runtime rejects that path. The current comparison
uses the explicitly identified, legal `compact64` anchor. Game measurements and
the eight-frame genuine replay used earlier application binaries with the same
selected Q32 shaders; their identities are recorded separately and do not
constitute new game benchmarks of the final release binary.

## Download and install

Download **OpenNR-AMD-v0.1.0-alpha.2-rx9070xt.zip** and its **.zip.sha256** asset.
The ZIP contains prebuilt runtime/host binaries, compiled shader inputs,
diagnostic and importer tools, install/remove scripts, notices and corresponding
source. GitHub's automatic **Source code** archives do not contain built DLLs.

Follow the included `INSTALL.md` or the
[alpha 2 installation guide](https://github.com/spydrful/OpenDLSS-NR-AMD/blob/v0.1.0-alpha.2/docs/INSTALL.md).
Requirements are Windows 11, RX 9070 XT, an AMD driver with the required RDNA4
FP8 matrices and wave32 execution, PowerShell 7, Microsoft Visual C++ v14
Redistributable x64, the installed game and your own supported local model DLL.
Adrenalin 26.9.1 and Cyberpunk 2077 2.31 are the tested versions.

Close the game and remove an existing installation using its own package before
installing into the game's **bin/x64** folder. Import the pinned 310.8.0 or
310.8.SF.0 container locally; the importer reads it without loading or executing
the DLL. The guide lists accepted hashes. **NVIDIA DLLs, extracted model weights
and game captures are excluded from the download and repository.**

After import, press **Insert → Neural → Enable NR** to opt in. Defaults retain
K16 publication arithmetic and qualified auto kernel selection. Use the checkbox
to disable inference; zero effect strength still runs the network. Keep the
package and install ledger/backups for removal. Preserve edited managed files
and follow the guide before removing or upgrading.

## Included changes

- The default INI disables NVIDIA Streamline capability spoofing with
  `[Spoofing] StreamlineSpoofing=false`. This FSR-based AMD integration does not
  need that path; an NR-disabled startup crash was traced to its cached
  capability pointer in the unchanged host, before the neural runtime loaded.
  Retain this setting when supplying a custom INI.
- Compact window attention with 16-, 32- or 64-query workgroups, full physical
  K/V ordering, shifted-window bounds and learned-prior indexing. Matrix
  epilogues use explicit tiles without assuming accumulator lane coordinates.
- `auto`, `baseline` and `optimized` diagnostic kernel selectors; explicit
  arithmetic, GEMM tile/staging, window query, fusion and publication controls.
  K32/final remain experimental; alpha auto selections require K16 preservation.
- Shared-memory guards reject the original legacy attention's 34,816-byte
  requirement on this 32,768-byte-limit GPU, including an explicit `baseline`
  request. The original shader and historical frozen evidence remain retained;
  there is no resource-limit override. New comparisons use the explicitly
  labeled `compact64` anchor: optimized K16/N16/stage16/Q64 with every fusion
  and hardware-publication flag off, bound to actual execution identities.
- Qualified tuning tied to device, driver, model, shader and session geometry.
  A shader-directory `amd-tuning.json` is included only when supplied during
  packaging, is hashed as managed payload and is checked at runtime. Every
  record must bind the complete measured policy. Missing or altered policy
  evidence rejects old caches before variant loading; auto retains the legal
  qualified Q64 fallback when available. Without a qualified path
  within the GPU's resource limits, inference is refused and the game bypasses NR.
- Separate ordinary paired network benchmarks and instrumented per-dispatch
  profiles with raw timestamp samples, metadata and instrumentation overhead.
  Evidence validation and tuning export tools inspect actual binary artifacts.
- Optional pinned portable RGA download and CPU-only wave32 resource/ISA
  analysis. Offline compiler evidence is distinct from installed-driver evidence;
  RGA binaries are not redistributed in this package.
- Bounded `capture.flag` requests for 1–120 NR submissions (empty means one),
  atomically published frame manifests, and sequence replay with both identical
  and independently evolved histories. Capture jobs are excluded from ordinary
  timing records, and captured assets remain local.
- MIT neural core/importer notices and GPL-3.0-or-later adapter/host corresponding
  source, dependency source archives and Windows build/install scripts.

## Validation and limits

The current legal Q64/Q32 comparison passes **657 operators / 858 strict
byte-preservation checks**. The target Q32 path also matches all 75 captured
graph boundaries and the F32 head at 320 x 320; its target head matches Q64
across **6,635,520 F32 values**, and its composed RGB matches across
**4,916,160 values**, including production-versus-decomposed checks.
Earlier compact variants also passed comparisons against the frozen legacy AMD
K16 implementation. The controlled D3D12 bridge harness passes
eight queued frames with the fusion variants. These checks establish
preservation of the existing accelerated AMD arithmetic; they do not establish
original NVIDIA runtime parity or visual quality with independently evolving
game history.

Hardware half publication remains disabled and unqualified after 780 of 858
strict checks failed. Offline ISA shows packed round-toward-zero conversion
where the software contract requires round-to-nearest-even publication. The
installed-driver cause remains an inference until that rejected variant's ISA
is inspected; the recorded finite-value witness already rules out a difference
limited to subnormals. Fusion and altered K32/final arithmetic remain opt-in
experiments.

Eight genuine target-resolution game frames also pass every PSNR/SSIM threshold against the portable exact reference with identical and independently evolved histories (minimum 49.536 dB / 0.998920 and 48.519 dB / 0.998642). Their preserving replay reproduces captured production output byte for byte. This short alley sequence does not satisfy the broader scene and visual-review gate.

The
[performance implementation record](https://github.com/spydrful/OpenDLSS-NR-AMD/blob/v0.1.0-alpha.2/docs/amd-performance-implementation.md)
provides identities, resource reports, measured variants and reproducible
qualification commands. Historical alpha 1 game measurements remain in the
[validation record](https://github.com/spydrful/OpenDLSS-NR-AMD/blob/v0.1.0-alpha.2/docs/rx9070xt-validation.md);
their 4.56–4.57 application FPS and approximately 213 ms NR-plus-bridge results
are not measurements of this optimized release.

Broad motion, faces, moving objects, disocclusion, exposure and camera-cut
quality review remain pending. Fresh synthetic HDR scene-linear comparisons
still fail quality gates across K16/K32/final arithmetic. RX 9070 XT is the sole
validated GPU; RX 7000 acceleration, other games/platforms, ray tracing and HDR
display validation remain later work. Report versions, settings, kernel policy,
status, timings and error text, excluding proprietary files and captures.
