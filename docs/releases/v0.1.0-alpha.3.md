# OpenNR AMD Alpha 3

An **experimental Windows build for Radeon RX 9070 XT and Cyberpunk 2077**. This release is for trying and validating neural rendering (NR); performance and broad game-quality targets remain unmet. **NR starts disabled.**

## What changed

- Makes the network's matrix calculations faster while preserving the existing AMD results.
- Adds tuned selections and stricter checks that a selected optimization matches the device, model and shaders.
- Adds separate experiment controls and isolated builds for developers.

This is an older development release. [Alpha 6](https://github.com/spydrful/OpenDLSS-NR-AMD/releases/tag/v0.1.0-alpha.6) contains the newer work; use this page when testing or returning to alpha 3.

## Get started

The tested setup is **Windows 11, RX 9070 XT, Adrenalin 26.9.1 and Cyberpunk 2077 2.31**, plus **PowerShell 7**, the **Microsoft Visual C++ v14 x64 runtime**, and your own supported local model DLL (pinned DLSS-NR 310.8.0 or 310.8.SF.0).

1. Download the ZIP and checksum, verify the hash, and extract the package. Keep it for removal.
2. Close the game. Follow the [installation guide](https://github.com/spydrful/OpenDLSS-NR-AMD/blob/v0.1.0-alpha.3/docs/INSTALL.md) to install into the folder containing `Cyberpunk2077.exe` (normally `bin\x64`). Preview the install with `-WhatIf` first.
3. Import your supported model locally using the guide. The importer reads the DLL without executing it; reuse an existing verified model rather than overwriting it.
4. Start with **2560 × 1440 output, FSR Quality, ray tracing off, frame generation off and driver AFMF off**. Launch the game, then press **Insert → Neural → Enable NR** when ready to test.

Use **Enable NR** to turn inference off again. Setting effect strengths to zero still runs the network.

## Upgrade or go back

Close the game and remove the current OpenNR installation using its own retained package before installing another version. Keep the extracted packages, the game's `.open-nr-install.json` ledger and `.open-nr-backup-*` folder. The scripts verify managed files and restore backed-up originals.

If you edited a managed INI or another installed file, preserve it and follow the guide before uninstalling; changed managed files can block removal. Imported models remain after uninstall. To return to an earlier release, uninstall this one, install that release using its own package and guide, and keep its packaged defaults.

## Known limits

The recorded game benchmarks average 97.12 FPS with NR off and 10.69 FPS with NR on. The separate 31.97% network improvement does not meet the NR-plus-bridge or 60 rendered FPS targets.

Broad motion, faces, disocclusion, exposure, ghosting and highlight acceptance remain incomplete. Some HDR/highlight reference-quality checks still fail. Original NVIDIA-runtime parity, RX 7000 acceleration, other games/platforms, ray tracing and HDR display validation are unclaimed. The full validation scope and measurements remain below.

[Report an issue](https://github.com/spydrful/OpenDLSS-NR-AMD/issues/new) with the release version, GPU/driver, game settings, selected NR options and exact error text. Keep proprietary DLLs, model files and game captures out of attachments.

# RX 9070 XT native Windows alpha 3

This development alpha adds a preserving direct-operand FP8 GEMM route to the
native Vulkan neural runtime, independent FFN32/QKV32 controls, stricter policy
and JSON validation, and isolated Windows experiment builds. It targets
**Cyberpunk 2077, native D3D12, RX 9070 XT**. Performance and broad game-quality
gates remain unmet; **NR ships disabled**.

Automatic cache GPU validation, bounded captured-history replay and
package/source-build checks pass; three warmed game benchmarks per condition
are complete.
The measured performance remains far above the requested budget. The
published alpha 2 assets and tag remain unchanged.

## Measured network improvement

The final diagnostic binary measures **119.143 → 81.049 ms median**,
**120.737 → 81.907 ms P95** and **121.066 → 82.602 ms P99**, at valid 1707×960,
padded to 1728×960. Three interleaved baseline/candidate pairs each use five
warmups and 30 measured frames, with image readback and dispatch instrumentation
off. Median inference falls **31.97%** against the already-qualified Q32/shared
GEMM anchor; this result does not recredit the earlier Q32 attention gain.

Both conditions use K16 publication, N16/stage16, Q32 attention and every
fusion/publication experiment off. These are **network-only GPU timestamps**,
excluding D3D12 bridge, FSR, game work and presentation. They establish neither
game FPS nor the **8 ms NR-plus-bridge / 16.67 ms complete-frame** targets.

The alpha 3 runtime completes three warmed built-in benchmarks per condition:
**97.32706 / 97.48801 / 96.55299 FPS NR off**, and
**10.70176 / 10.69026 / 10.69028 FPS NR on**. Equal-pass means are
**97.12269 / 10.69410 FPS**. Complete NR-on exports have pooled
**93.495 ms median / 95.0625 ms P95 / 95.9785 ms P99**, over 2,916 frames.
Separate asynchronous completed-runtime brackets have NR-plus-bridge medians
**85.84388 / 85.94782 / 85.90282 ms** and zero bypass-count increase. The maximum
observed process-local DXGI sample is **9,428.008 MiB**, not a true interval peak.
Runtime jobs are not joined to game presents; no PresentMon was collected.

The game uses 2560×1440 windowed output, FSR3 Quality, target High fields
labelled Custom, with game/driver frame generation, ray tracing and AFMF off.
The unchanged enabled driver FSR upscaling override leaves the exact effective
FSR version independently unverified. Warmups, an earlier untraced NR-on pass
and a black-screen marker are excluded. The
[alpha 3 game evidence](https://github.com/spydrful/OpenDLSS-NR-AMD/blob/v0.1.0-alpha.3/docs/performance/cyberpunk-alpha3-20261002.json) binds
these measurements to the loaded runtime and records their scope. The
[alpha 2 validation record](https://github.com/spydrful/OpenDLSS-NR-AMD/blob/v0.1.0-alpha.2/docs/cyberpunk-alpha2-validation.md) retains its
historical 97.66 / 7.55 FPS results and binary identities unchanged.

## Included changes

- Direct aligned packed operand loads replace GEMM operand shared-memory
  staging while retaining original accumulator initialization, ordered K16
  operations, half publication, split-K reduction and residual/activation
  placement. The guarded shader has a distinct module and measured route.
- `--amd-gemm shared|packed|direct` and `DLSS5VK_AMD_GEMM` bind the actual
  route in logs, model fixtures, replay and tuning evidence. Direct requires
  stage K16. The original shared kernel remains available as the preserving
  fallback; packed staging remains a separate diagnostic candidate.
- A **46-record qualified target-geometry direct-GEMM cache** binds GPU,
  driver, model, shader, arithmetic, route, tile and independent fusion policy.
  Invalid records reject the optimized selection and retain a qualified
  fallback when available. Forced diagnostics cannot silently claim a
  different actual route.
- Independent `--amd-ffn32-fusion` / `--amd-qkv32-fusion` and process environment
  overrides allow each C32 route to be tested separately. The existing fusion
  shorthand selects both. They remain opt-in; independent 320 model checks
  are not a target performance promotion.
- The `qualified32` diagnostic anchor explicitly compares against optimized
  shared GEMM/K16/N16/stage16/Q32 with all experiments off. Old evidence without
  a GEMM field describes shared GEMM only; it cannot qualify a new route.
- Pipeline keys include actual shader modules so geometry tuning cannot reuse
  another route's compiled pipeline. Explicit Vulkan ordering and the version
  1 C lifecycle ABI remain intact.
- Optional `-OutputDirectory` on core, shader, runtime and interop build scripts
  enables isolated Windows builds. Harness runtime selection accepts a matching
  isolated DLL and local assets without installing into the game.
- Bounded JSON parsing rejects malformed literals, duplicate decoded keys,
  invalid strings/UTF-8 and nonfinite/unrepresentable numbers. Policy validation
  binds complete selected-policy evidence and independent routes.

## Validation and remaining limits

The clean public operator suite passes **660 operators / 862 strict checks**,
comparing **14,123,008 bytes**, including overdispatch and canary checks.
Preserving model comparisons pass all **75 boundaries, the F32 head and composed
RGB at 320×320**. Target head/composition and production/decomposed comparisons
also pass. Independent FFN32-only and QKV32-only direct-GEMM 320 runs pass the
same model boundaries and head. The zero-initialized accumulator experiment
fails **160 partition checks** and is excluded.

The controlled new-runtime harness passes shared GPU buffers/fences, pack and
exposure conversion, command-list continuation, eight-slot continuous and
cancel/gap/reset ownership, recovery, resize, drain and shutdown. These checks
do not replace new complete game measurements or visual review.

Eight existing genuine SDR game frames pass reference quality thresholds in
both identical/evolved history modes: minimum **51.330 dB / 0.999792 SSIM** and
**50.525 dB / 0.999676 SSIM** respectively. New Direct and final alpha 2 Shared
candidate output match across **80 byte checks / 2,107,883,520 bytes** in both
modes. This replays existing captures and establishes no new scene/motion
coverage. Automatic cache GPU selection reports actual Direct/Q32/K16 with
all experiments off. Installer/package checks pass **19 / 67 checks**; the
source package rebuild passes and reproduces all 24 core and two game SPVs.
EXE/DLL binary reproduction is not claimed.

Offline RGA wave32 analysis covers all **32 actual GEMM specializations / 358
target GEMM dispatches**. Direct/shared compiled LDS is **4096 / 5632 bytes**,
VGPR is **18–28 / 22–32**, and reported scratch/spills are zero. FP8 matrix static
counts are unchanged; packed global loads replace operand LDS transfers and
static barriers decrease. Offline resources and static ISA do not prove
installed-driver occupancy or executed instruction timing.

The [GEMM delivery record](https://github.com/spydrful/OpenDLSS-NR-AMD/blob/v0.1.0-alpha.3/docs/amd-gemm-delivery.md) and
[scalar evidence](https://github.com/spydrful/OpenDLSS-NR-AMD/blob/v0.1.0-alpha.3/docs/performance/direct-gemm-rx9070xt-20261002.json) bind these
results to source, compiler, shader and binary hashes. Broad
motion/face/disocclusion/exposure/camera-cut review, scene-linear highlight
acceptance and ten minutes of active gameplay remain pending. K32/final
arithmetic and fusion remain separate experiments. Original NVIDIA-runtime
parity, RX 7000 acceleration, other games/platforms, ray tracing and HDR display
validation are not established.
