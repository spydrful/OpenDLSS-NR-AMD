# RX 9070 XT native Windows alpha 4

This development alpha adds preserving scalar FP16 round-to-nearest-even
publication and compact register attention to the native AMD Vulkan runtime.
It targets **Cyberpunk 2077, native D3D12, RX 9070 XT**. NR ships **disabled**;
the 8 ms NR-plus-bridge and 16.67 ms / 60 FPS complete-game targets remain unmet.

Release:
[v0.1.0-alpha.4](https://github.com/spydrful/OpenDLSS-NR-AMD/releases/tag/v0.1.0-alpha.4).
Previous alpha releases, assets and their measurements remain unchanged.

## Measured network improvement

Ordinary target network GPU timing improves **82.224740 → 58.527400 ms median**,
**82.513122 → 58.883906 ms P95** and **82.560180 → 58.993574 ms P99**:
**28.8202% median improvement** against the immutable alpha 3 Direct/staged route.
Three interleaved baseline/candidate pairs each use five warmups and 30 measured
frames, with image readback and dispatch instrumentation off.

Both conditions run one full-resolution pass at valid **1707×960**, padded to
**1728×960**, with K16 publication, N16/stage16/Q32 and every fusion/packed-publication
experiment off. Windows 11, Adrenalin 26.9.1 (LLPC) and RX 9070 XT are the qualified
environment. These are **network-only GPU timestamps**, excluding the bridge,
FSR, game and presentation. They do not establish game FPS.

Separate instrumented profiles report medians of actual per-frame family sums:
FP8 GEMM **49.735 → 39.039 ms**, window attention **21.512 → 8.012 ms**. Ordinary
network timing supplies the performance gate. The
[RTE delivery record](https://github.com/spydrful/OpenDLSS-NR-AMD/blob/v0.1.0-alpha.4/docs/amd-rte-delivery.md)
and [scalar evidence](https://github.com/spydrful/OpenDLSS-NR-AMD/blob/v0.1.0-alpha.4/docs/performance/rte-kernels-rx9070xt-20261003.json)
pin the actual binaries, shader policies, model, driver and timing scope.

**Alpha 4 game FPS has not been measured.** Historical alpha 3 means were
**97.12 FPS NR off / 10.69 FPS NR on**; they retain their
[alpha 3 identities](https://github.com/spydrful/OpenDLSS-NR-AMD/blob/v0.1.0-alpha.3/docs/performance/cyberpunk-alpha3-20261002.json).
New complete game benchmarks and ten-minute active gameplay remain pending.
Windows UI activation/recovery failed before the test preview was installed;
game settings remain unchanged.

## Included changes

- `amd_gemm_direct_rte` replaces software matrix half publication with qualified
  scalar `OpFConvert`, retaining ordered K16 operations, residuals, partition
  reductions and activation placement. The original Direct route and portable
  exact reference are unchanged.
- Separate `amd_window_register` / `amd_window_register_rte` modules stage raw
  packed E4 words and publish typed FP16 scores. Register-RTE also accelerates
  prescribed softmax half operations. Physical key order, exponent approximation,
  reduction order, shifted windows, padding and E4 publication remain unchanged.
  LDS is **9,728 bytes at Q16 / 13,312 bytes at Q32**; original staged shaders
  remain reproducible.
- `--amd-gemm direct-rte` and `--amd-window-layout staged|register|register-rte`,
  with process-environment equivalents, select distinct actual routes. RTE
  requires supported FP16 rounding/denormal/signed-zero/Inf/NaN controls;
  register attention requires the enumerated FP16 accumulator matrix type and
  Q16/Q32. Unsupported forced selections fail visibly.
- A **68-record qualified target cache** selects Direct-RTE/Register-RTE,
  K16/N16/stage16/Q32 for matching device, driver, model, shader and geometry.
  Complete policies and exact variants are bound to operator evidence. Old
  missing-layout records mean staged and cannot qualify the new modules.
- `direct32` compares against the prior Direct/Q32/K16/staged policy. Earlier
  `qualified32` and `compact64` anchors retain their meanings. K32/final and
  fusion remain separately labeled opt-in experiments. Capture keeps the same
  selected arithmetic policy. Queue/fence ordering and the v1 C ABI are unchanged.
- Three complete paired protocols on the frozen original alpha 3 Direct/staged
  route reject FFN-only, QKV-only and combined fusion: inference median increases
  **23.19%, 25.57% and 50.45%**. The routes stay off. This evidence is separate
  from RTE timings and does not evaluate a redesigned RTE fusion implementation.

## Validation and remaining limits

The named K16 route passes **660 operators / 862 strict byte checks /
14,123,008 bytes**. All **75 model checkpoints plus the F32 head at 320×320**
match the alpha 3 AMD baseline, including production/decomposed reproduction.
Target head reproduction passes; automatic cache selection also passes target
composition and capture. All 75 target boundaries were not exported.

Synthetic SDR/HDR preservation passes **36 buffer checks / 98,304,096 bytes**.
Replay of eight existing SDR game frames passes **80 byte checks /
2,107,883,520 bytes** against alpha 3 in identical and independently evolved
histories. Reference-quality minima remain **51.330 dB / 0.999792 SSIM** and
**50.525 dB / 0.999676 SSIM**, using unclamped scene-linear RGB and data range 1.0.
This adds no new visual coverage and leaves existing HDR-highlight quality
failures unchanged.

Controlled shared-buffer/fence, imported-DLL ABI/lifecycle and eight sequential
target-frame checks pass. The separate eight-slot queued-output ownership and
prefetched/serialized equality proof runs at **320×320**; a target-resolution
eight-prefetched-output equality proof is not claimed. The conversion probe
passes 1,861,036 witnesses on the qualified driver; offline RGA and installed-driver
executable statistics retain their separate scopes. The Vulkan validation layer
was absent, so zero diagnostic errors are not a validation-layer claim.

Installer/package/build-path checks pass **19 / 67 / 50 checks**. A fresh
corresponding-source build passes the core, runtime, importer tests and GPL host,
reproducing all **27 native SPIR-V modules**. Identical rebuilt EXE/DLL bytes are
not claimed.

Broad motion, faces, moving objects, disocclusion, exposure, cuts, flicker and
ghosting review, scene-linear highlight acceptance, complete game benchmarks
and ten minutes of active gameplay remain pending. No original NVIDIA parity,
RX 7000 acceleration, other-game/platform support, ray tracing or HDR display
validation is established.

## Install and remove

Download **OpenNR-AMD-v0.1.0-alpha.4-rx9070xt.zip** and its
**.zip.sha256** asset. Follow the
[alpha 4 installation guide](https://github.com/spydrful/OpenDLSS-NR-AMD/blob/v0.1.0-alpha.4/docs/INSTALL.md).
GitHub's automatic source archives do not contain built DLLs.

Use Windows 11, RX 9070 XT, tested Adrenalin 26.9.1, PowerShell 7 and the
Microsoft Visual C++ v14 x64 Redistributable. Cyberpunk 2077 2.31 is the initial
game target: 2560×1440 output, FSR Quality, ray tracing and frame generation off;
disable driver AFMF for rendered-frame measurements.

Close the game and remove an existing OpenNR installation with its own package
first. Install into `bin\x64`, import your supported model locally, then select
**Insert → Neural → Enable NR** to opt in. Preserve the package, installation
ledger and backups for reversible removal. Zero effect strength still runs NR.

**NVIDIA DLLs, extracted weights and game captures are excluded** from the
repository and download. The importer reads the supported DLL without executing
it. Packages retain MIT core/importer attribution, GPL adapter/host notices and
corresponding source and build scripts. Final package/source-build verification
is recorded with the tested artifacts; final download and publication identities
are recorded when delivery completes.
