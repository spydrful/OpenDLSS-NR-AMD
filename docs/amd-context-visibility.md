# Buffer synchronization validation

The diagnostic buffer helpers now record explicit memory dependencies around uploads, fills, and CPU readback. Each download makes prior compute/transfer writes visible to its copy, then makes the staging copy visible to the CPU before the queue wait returns and mapped bytes are read. Range checks also reject wrapped offset/size values. Vulkan fence waits establish completion but do not provide host-read visibility by themselves. [Vulkan specification](https://docs.vulkan.org/spec/latest/chapters/synchronization.html), [Khronos readback example](https://docs.vulkan.org/guide/latest/synchronization_examples.html#_cpu_read_back_of_data_written_by_a_compute_shader).

The fix passed 20 CPU contract checks and eight GPU buffer round trips, including uploads and offset reads larger than the 256 MiB staging buffer. Fresh CLI diagnostics passed 934 exact operator checks (15,264,768 compared bytes), all 75 model checkpoints plus nine block-0 intermediates and the F32 head at 320×320, and the F32 target head and capture at 1707×960 (padded to 1728×960). Their bytes match the frozen local AMD results. These runs used the existing diagnostic Pair/Arena K16 policy; all 31 native shader modules, arithmetic, default tuning cache, ABI and game bridge are unchanged.

Fresh native DLL lifecycle tests passed at 320×320 and 1707×960 with eight requested-geometry frames serialized. The separate source-included production runtime pool prepared eight distinct live slots before submission and reproduced continuous eight-frame and cancel/gap/reset seven-frame outputs at both geometries. Shared buffer/fence round trips, resource/command-list continuation, cancellation, resize, reset, drain and shutdown passed. This does not demonstrate parallel inference or gameplay. These are correctness checks; no ordinary performance, scene-linear quality, game FPS or kernel promotion claim is made. GPU validation layers were not enabled. Existing releases and the disabled-by-default state remain unchanged.

Earlier readback diagnostics lacked these explicit dependencies. Their recorded comparisons remain historical observations; they do not qualify new source. The fresh checks above reproduce the retained AMD output bytes with the repaired helpers. Readback-free ordinary timing reports retain their original binary identities and are not new timing measurements of this fix.

The [scalar evidence](performance/context-visibility-rx9070xt-20261003.json) records the source, binaries, driver, shader identities and checks.[^publication] No tensors or weights are included. Run the CPU dependency/range checks with `scripts/test_vk_readback_cpu.ps1 -OutputDirectory <fresh directory>` after installing the [Windows build prerequisites](AMD.md#build-and-local-checks). GPU checks require the supported card and your own imported model.
